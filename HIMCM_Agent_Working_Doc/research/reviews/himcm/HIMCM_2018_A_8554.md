## Problem demand map

The paired official problem asks for an objective descriptive ranking from numerical/descriptive specifications, a world top ten, comparison with at least two online systems, an app concept and a one-page nontechnical news release. The supplied dataset intentionally contains incomplete/noisy values and is a selected subset of operating, above-average coasters. The paper supplies each requested output: repair procedures (pp.5–8), ranking model (pp.8–12), comparison (pp.12–13), app concept (pp.14–18) and news release (p.2). The analysis nevertheless only ranks 300 supplied coasters; a world-wide label requires a qualification about this candidate universe.

## Full model architecture and rationale

`Raw records → categorical corrections → type/construction partition → nearest-neighbor or cluster-assisted imputation → numeric encoding → five experience indicators → entropy-weighted general ranking or preference-weighted personal ranking → app filters and recommendation screens.`

For sparsely missing speed/length, the authors choose the closest peer of the same material/type using relative differences in other dimensions (pp.5–6). For more heavily missing fields they cluster wooden coasters separately, then split steel coasters by inversion status. The stated reason is that comparable designs should have similar attributes (pp.6–8). They explicitly widen clusters when too few observed values remain, acknowledging increased estimation error. This is more informative than treating imputation as an invisible preprocessing step.

Five intermediate indicators translate specifications into ups-and-downs, vertigo, sustainability, stimulation and nostalgia. The paper avoids counting both the binary presence of inversion and its count as independent vertigo evidence (p.10). Entropy weighting assigns weights according to feature variation, first within composite indicators and then across the five indicators for the generic ranking (pp.9–12). User coefficients replace the outer weights for personalized rankings. App filters restrict construction/type before ranking the remaining candidates (pp.14–15).

**Reviewer inference:** the useful structural idea is separation of descriptive components, an aggregation policy and user constraints. The same component table can power a general ranking and a personal recommendation. Calling an entropy formula objective describes how weights are computed; it does not establish that the selected indicators, encodings or monotonic preferences objectively measure enjoyment.

## Data, assumptions and weights

The authors correct three categorical records with material names placed in the type field (p.5). They report missingness separately for wooden-coaster drop, duration, angle and G-force fields; only seven of fifty wooden records have G-force data (p.7). The assumption that an unreported G-force implies no acceleration system leads to a default 2G value. This is a substantive missingness assumption, not a measured fact; clustering cannot validate it.

Material is encoded as steel=1 and wood=0.828 using mean height/speed contrasts. Six seating/track types receive ordinal scores 1–6 (p.9). The first encoding risks representing height/speed again after those variables already enter other indicators; the second assumes equally spaced psychological differences without supporting measurement. Nostalgia increases with age (p.11). All main physical inputs are assumed to improve enjoyment monotonically, even G-force (pp.4–5); the conclusion acknowledges that high G-force can cause discomfort (p.19).

The reported sustainability weights are 0.0057, 0.0032 and 0.9911 for height, length and duration (p.11). Such domination is a prompt for a data/unit/normalization audit, particularly because duration was imputed. It is not evidence that duration explains 99% of enjoyment. The full corrected table, chosen cluster cuts, all encodings and final outer weights are not supplied as a reproducible computation bundle.

## Validation and evidence boundaries

External comparisons list overlap with Ranker and TheTopTens and suggest seat position and price as possible explanations for disagreement (pp.12–13). These are plausible hypotheses, not tested causes. Agreement with a voting site is contextual validation of face plausibility; it neither proves objectivity nor determines which ranking is correct.

The sensitivity exercise removes the bottom 100 candidates, recomputes the ranking, and finds broadly similar leaders, including a swap between second and third and a replacement in tenth place (pp.13–14). This tests a specific change in the candidate population. It does not test the uncertain imputed values, alternate cluster cuts, G-force defaults, encodings or preference coefficients. No held-out imputation test is reported. A cophenetic coefficient close to one, mentioned without a displayed numerical result in the conclusion, concerns dendrogram representation and is not proof of accurate missing-value predictions (p.19).

The app has useful mock-ups and three illustrated recommendation paths (pp.17–18). Learnability, efficiency, memorability and satisfaction are argued from the interface structure (pp.16–17). No usability experiment supports the claim of perfectly satisfying a standard; the sole two references are ranking websites (p.20).

## Static consistency checks

The stated normalized indicators and nonnegative coefficients summing to one imply a nonnegative bounded aggregate, yet published scores extend above five and below minus three (pp.11–12, 21–25). An unreported rescaling or different implementation may explain this; the manuscript alone does not. The three last scores in the baseline column of Table 7 also differ from the corresponding Table 5/appendix values (pp.12, 14, 21). These are reasons to check the actual computation, not grounds to invent a corrected ranking.

The introduction promises collaborative filtering and k-nearest-neighbor recommendations, but the later app model develops preference-weighted scoring and filtering without a corresponding learned recommendation experiment (pp.4, 14–18). A final scope audit should remove undeveloped method promises.

## Transfer to the working document

Make the data engineer report missingness by subgroup, retain a per-cell imputation flag and assess whether missingness depends on the missing value. Make the modeler distinguish data-derived weights from value judgments and audit double counting. Require the validator to mask known entries for imputation checks and propagate plausible imputation/weight alternatives to rank stability. Test aggregation range invariants before writing results. Let the writer explain the recommendation pipeline through concrete screens and input/output examples, while preserving the distinction between a designed user experience and one validated with users.
