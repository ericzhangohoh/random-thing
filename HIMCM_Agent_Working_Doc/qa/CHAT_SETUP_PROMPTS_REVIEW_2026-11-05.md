## Contract findings

Each full prompt repeats the setup-only boundary and readiness response. The common contract explicitly makes the older bootstrap and assignment examples non-executing examples during initialization. This prevents an agent from treating reading the workflow as authority to create control files or start a contest solution.

`REPO_ROOT` and `DOC_ROOT` are concrete, while the active `PROJECT_ROOT` remains unassigned unless explicitly supplied. The prompts distinguish the reusable manual, the completed 2022 rehearsal and the newly downloaded candidate 2026 statements. They do not inherit a selected problem, historical practice delegation, previous PDF acceptance, or live-contest publication/submission authority. An unassigned active root is a normal setup result rather than a reason for every worker to ask the user the same question.

The 11 responsibilities are distinguishable. The scientific verifier focuses on mathematics, code and result correspondence. The model attacker tests consequential assumptions and alternatives. R1, R2 and R3 each read the entire paper under a different lens. The final artifact reviewer checks the actual export after the author and three complete sentence-review chains close. The six base roles and five specialized assignments are correctly described as a suggested roster, not as proof that 11 agents are already running.

Future directory defaults require task-specific narrowing before any write. The coordinator alone owns active control records and authorized Git changes. Workers and reviewers own explicit task paths and their own handoff. Reviewers do not repair targets or peers' reports. The three sentence-review path patterns are distinct, and the coordinator is required to allocate disjoint QA paths for the other reviewers too. The setup turn remains read-only for every role, including the coordinator.

The readiness contract is usable: actual files read, repository/root, responsibilities, expected inputs, future write boundary, expected outputs and handoff, missing capabilities, and authorship/independence when relevant. Missing reading produces `SETUP_INCOMPLETE`. Successful setup produces `READY_FOR_ASSIGNMENT`, which is expressly separate from acceptance of scientific work. Agents finish the turn instead of polling indefinitely.

Handoffs preserve exact versions and scope. The default route is durable files plus human relay, with no assumption that a shared project grants shared conversation context or automatic notification. Direct messaging requires human authorization, available tools and real destination IDs. Earlier authorization remains valid within its stated scope, so the prompts do not impose blanket repeat-confirmation requirements for later assigned reversible work.

Review independence and completeness are explicit. Each sentence reviewer forms findings before reading peer critiques, searches for omitted text, supplies individual judgments, and rechecks changed context and exact versions. A role name does not erase authorship. The source/PDF/font/punctuation requirements preserve the user's LaTeX, actual Times New Roman, monochrome and combined maximum-three-semicolon brief, while requiring current contest rules to be checked when live work actually begins. Natural prose guidance preserves meaning, evidence and disclosure.
